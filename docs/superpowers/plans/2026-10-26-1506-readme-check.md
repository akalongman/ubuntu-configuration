# README Check Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `bin/check-readme` script, run by GitHub Actions on `24.04`, that reports TOC and link mistakes in `README.md` on the line that caused them.

**Architecture:** One standard-library Python script parses the README once (headings outside fenced code, TOC items, links), runs four checks and prints one line per problem. A unittest suite drives the script as a subprocess against small temporary READMEs. A workflow on `24.04` runs the suite and then the script.

**Tech Stack:** Python 3 standard library (`re`, `difflib`, `pathlib`, `urllib.parse`, `unittest`, `subprocess`), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-26-1451-readme-check-design.md`

## Global Constraints

- Python standard library only. No `requirements.txt`, `pyproject.toml` or `package.json`.
- No syntax newer than Python 3.12 (the runner has 3.14.4; 3.12 keeps `ubuntu-24.04` viable).
- `bin/check-readme` starts with `#!/usr/bin/env python3` and is committed with mode `100755`.
- Plain output, one line per problem, sorted by line: `<path>:<line>: <message>`.
- When `GITHUB_ACTIONS=true`: `::error file=<path>,line=<line>::<message>`, with `%`, `\r`, `\n` in the message escaped as `%25`, `%0D`, `%0A`.
- Exit status 0 when clean, 1 on problems, 2 when the file cannot be read or has no `# Table of Contents` section (the unreadable case is a plan call; the spec names only the missing section). Exit-2 messages go to stderr as `<path>: <reason>`.
- Anchor rules: lowercase, drop every character except letters, digits, `_`, `-` and space, turn each space into `-`, suffix repeats with `-1`, `-2` in document order. Letters of any script count (`re` `\w` is Unicode-aware).
- Lines inside fenced code (`` ``` `` or `~~~`) are never headings or links.
- External URLs (`http:`, `https:`, `mailto:`) are never fetched or checked.
- The workflow exists only on `24.04`, runs on `ubuntu-26.04`, and pins `actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1`.
- Release-branch link suggestion base: `https://github.com/akalongman/ubuntu-configuration/`.
- No em or en dashes in any text: messages, comments, docs, commit messages.

## Review Focus

1. The suite runs inside the workflow, where `GITHUB_ACTIONS=true` is already set: the plain-output tests must still pass. Task 1's helper removes the variable unless a test asks for it, and Task 3 runs the suite with it set.
2. Non-ASCII headings (the README has a Georgian keyboard section): a Georgian heading keeps its letters in the anchor. Task 1, `test_anchor_rules`.
3. Trailing whitespace after a heading (README line 493 today), closing `##` sequences, and CRLF line endings from another editor all leave the anchor unchanged. Task 1, `test_anchor_rules` and `test_crlf_readme`.
4. Fence edge cases: a closing fence with trailing spaces (the README has one), `` ``` `` inside `~~~`, info strings like `` ```bash ``. Task 1, `test_fenced_hash_lines_are_not_headings`; Task 2, `test_links_in_fenced_code_ignored`.
5. One mistake gives one message: a missing entry, a misplaced entry, a merged line or a missing `#` must not cascade into later entries or be re-reported by the link checks. The Task 1 and Task 2 tests assert exact output lists, not membership.

```python
def doc(entries):
```

- [ ] **Step 4: Implement `bin/check-readme` with the Task 1 interfaces**

- Heading: `^ {0,3}(#{1,6})[ \t]+(.*?)(?:[ \t]+#+)?[ \t]*$` on a non-fenced line. A fence opens on `^ {0,3}(`{3,}|~{3,})` and closes on a line of the same character, at least as long, with only whitespace after it.
- Markup guard: heading text matching `\[[^\]]*\]\(|<[A-Za-z/!]|(?<!\w)_|_(?!\w)` is a problem (an intraword `_` as in `mod_rewrite` is fine; backticks and `*` are dropped by the anchor rule, as on GitHub).
- TOC items: lines inside the section matching `^( *)- \[`; take every `- \[[^\]]*\]\(([^)\s]+)\)` on the line. More than one item on a line is the merged-line problem, and only the first item's indentation is checked. A target without `#` is reported, then aligned as if it had one.
- Alignment of TOC anchors against the anchors of headings after the section:

```python
sm = difflib.SequenceMatcher(None, toc_anchors, heading_anchors, autojunk=False)
# equal blocks: compare indentation with 4 * (level - 1)
# other blocks: anchors present on both unmatched sides are "out of order", reported once at the TOC line;
# the rest are "matches no heading" (TOC side) or "has no TOC entry" (heading side)
```

- Default path: `README.md` next to the script's parent directory, displayed as `README.md`; a given path is displayed as given. Read with `encoding='utf-8'`, split with `str.splitlines()`.

```yaml
name: README check

on:
  push:
    branches: ['24.04']
  pull_request:
    branches: ['24.04']

permissions:
  contents: read

jobs:
  check:
    runs-on: ubuntu-26.04
```
